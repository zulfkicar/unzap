Low validation loss is unsurprising on a small template-based dataset. It is not evidence that the model can migrate arbitrary workflows. Both training and evaluation are offline. Only the public model downloader has network access, and it has no dataset mount.

## Data boundary

Examples are authored fictional tasks based on supported contracts and observed source shapes. They do not contain private customer export literals, credentials, private code or recorded provider responses. All reference programs passed author-specified execution fixtures before training. The dataset builder supplies both reference programs and expectations. Those expectations are fixed before model generation and are not generated by either evaluated model. They are not an independent human audit or recorded provider ground truth.

Training and familiar-family evaluation vary payload fields, thresholds, domains and source IDs. Nested routing and lookup followed by routing occur only in test. Most familiar-family wording follows shared templates. Neither paraphrase robustness nor live SaaS equivalence has been established. Only six of the 20 validation examples contribute to the reported loss. Manifest hashes cover messages and targets, not the complete fixture data.

## Paired generation evaluation

The comparison selects one example from each of 12 test families, including two structural holdouts. It toggles the adapter on the same frozen base weights, using identical prompts, greedy decoding and a 1,024-token completion cap. No schema constraint, output repair or cleanup is applied. The remaining 12 test variants are not included in this run.

Every proposed workflow must preserve supplied source IDs and parents, pass the native compiler, and satisfy the task's authored fixtures. Fixtures compare statuses, final outputs and HTTP method, URL and body. API requests are mocked locally. Unsupported-action refusal is scored separately from executable workflow success.

All 12 requested pairs completed in 1,011.67 seconds, within the 1,200-second evaluation budget. There were no deadline-interrupted outputs. One base-model date response exhausted its 1,024-token allowance. The adapter exhausted none.

There were eight task wins and no regressions, with this small, template-based population. The base fails mostly at serialization, so the difference includes format learning. These numbers are not a comparison against the application's 4B agent, which uses schema-constrained generation and repair. No broad migration accuracy or statistical population estimate is claimed.

The adapter's four failing tasks are informative:

- **Numeric gate:** compiles, but filter keys contain literal field names rather than references. Every fixture holds with non-numeric data.
- **Raw Zap-shaped export:** malformed JSON, with visible trigger/ID and mapping errors in the raw generation. It cannot enter compilation.
- **Nested routing holdout:** valid JSON, but creates multiple fallback branches in one Paths group. The compiler rejects it.
- **Lookup-plus-routing holdout:** valid JSON, but uses an invalid trigger and omits lookup miss/multiple-match policy. The compiler rejects it.

Passing families were typed mapping, normalization, simple priority/fallback routing, lookup, date formatting, query construction and linear typed-source preservation. Refusal also passed. This supports a narrow conclusion: local LoRA training can improve the small translator's format and familiar contracts. The pilot did not establish unseen graph composition.

## Reproduction and promotion

See [the experiment instructions](../finetune/README.md) for Docker commands, split construction, resource limits and artifact locations. Four oracle regressions verify rejection of a compiler-valid semantic mutation, changed source identity, malformed proposal schema and an executable definition disguised as a refusal. The complete Node suite passes 50/50 with local loopback access.

The checkpoint is a PEFT adapter with a compact workflow proposal protocol. It is not an Ollama-ready artifact and has not been tested as the application's full tool-loop agent. It is not promoted because both structural holdouts failed. The next dataset should add reviewed source-to-definition pairs, richer field-reference supervision and deeper graph compositions. Keep this evaluation frozen and add fresh compositions to measure subsequent generalization. A larger, independently phrased test set and a direct comparison with the current 4B agent under the same protocol are also required. Missing runtime adapters must still be implemented in code.
